# إصلاح تسجيل الميكروفون — 2026-10-17

## التغيير

- يستعمل المسجل `CaptureAudioSource.Default` للحصول على معرّف ميكروفون Windows الافتراضي. المنشئ دون معاملات يترك `DeviceName` فارغًا ولا يختار جهازًا فعليًا.
- إذا لم يعد الميكروفون المختار متاحًا، يرجع التسجيل إلى ميكروفون Windows الافتراضي. إذا تعذر توفير جهاز صالح، يسجل التحذير في السجل التقني ويتجنب تمرير مصدر صوت غير صالح إلى المسجل.
- يستخدم صوت النظام، عند تفعيله صراحة، مخرج Windows الافتراضي. فشل أحد مصدري الصوت لا يعطّل المصدر الآخر.
- إعدادات Agent في الحزمة الجديدة تفعّل الميكروفون وتبقي صوت النظام معطّلًا. إعدادات المستخدم ثم الإعدادات المشتركة الموجودة سابقًا تتقدم على إعدادات الحزمة.
- لم تُضف نوافذ أو تنبيهات أو أيقونات من التطبيق. بقيت مؤشرات الخصوصية واستخدام الميكروفون في Windows كما هي.

مرجع سلوك المصدر الافتراضي: [المصدر الرسمي لمكتبة ScreenRecorderLib](https://github.com/sskodje/ScreenRecorderLib/blob/master/ScreenRecorderLib/AudioSources.h).

## التحقق

- نجح اختبار الصوت المخصص: 12 حالة تستخدم بيانات أجهزة بديلة دون فتح تدفقات صوتية.
- نجح الفحص الكامل: 93 حالة ناجحة، صفر إخفاق، و3 حالات تشخيص يدوي متجاوزة.
- نجح بناء Release ونشر Service وAgent وViewer بنسخة Windows x64 مستقلة.
- تحقق مستقل من جميع الملفات الـ952 المدرجة في قائمة SHA-256 الخاصة بالحزمة.
- تحقق من تفعيل الميكروفون وتعطيل صوت النظام داخل الحزمة، ومن أن ملف Agent التنفيذي يستخدم Windows GUI subsystem ولا يفتح Console.
- لم يُشغّل Agent، ولم يُلتقط صوت أو شاشة حقيقية. جودة التسجيل الفعلية والوصول إلى الميكروفون على جهاز التشغيل لم يُختبرا.
